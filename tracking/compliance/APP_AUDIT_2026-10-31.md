# Streamlit app audit and redesign (2026-10-31, branch `submission/clean`)

Scope: presentation and usability only. No model, weight, limit or output value was changed.
Sources compared: `outputs/` (pipeline snapshot), `docs/ASSUMPTIONS_LIMITATIONS.md`, `docs/AI_DISCLOSURE.md`,
`docs/DECISIONS.md` (D1–D44), memo / tear sheet / report, `config/settings.yaml`.

## Gaps in the redesign brief itself
| # | Gap | How it was handled |
|---|---|---|
| G1 | The hosted Streamlit Cloud app deploys from `version-1`, so a redesign on `submission/clean` is not visible to judges until the deploy branch changes. | Flagged for a team decision; no deploy setting or other branch was touched. **Resolved 2026-10-31:** the submission branch was published as `main` (the repository's default branch), and the Streamlit app was redeployed from `main`. The live app shows the redesign. |
| G2 | `AI_DISCLOSURE.md` is a **draft with an empty sign-off table** (brief §8.7). Making the page "concise" must not hide that. | The page shows the sign-off status computed from the file (members signed / rows). |
| G3 | `ASSUMPTIONS_LIMITATIONS.md` is the single source for the app and the report. Retyping it as tables would let them drift. | The page is generated from the file: sections and bullets are parsed, nothing is retyped. Short summaries are computed (first sentence of each bullet), the full text stays in expanders. |
| G4 | Streamlit 1.66 warns that `use_container_width` is scheduled for removal; every page used it. A future Streamlit Cloud upgrade would break the app. | Replaced by `width="stretch"` throughout. |
| G5 | Several figures on the Decision page were typed into the code (walk-forward 7.3%, Sharpe 0.89 vs 0.75, p = 0.15, −16.4% vs −19.2%). | Now read from `research_walkforward_summary.csv` and `research_v2_sharpe_test.csv`. |
| G6 | The checklist omits the out-of-sample period in which O6's weights did **worse** than the benchmark (2020–26: CAGR 5.0% vs 7.2%, Sharpe 0.30 vs 0.49). Leaving it out would overstate the case. | Shown on the Portfolio and Decision pages next to the walk-forward result. |
| G7 | The D44 AI / tech crash with inflation (22.8% severe, 31.2% at 1.5×) is in the report but not in the app. | Added to the Stress page from `research_v2_ai_inflation.csv`. |
| G8 | The app smoke test only checks that pages do not crash; it does not check that interactions work. | Test extended: the one-day backtest range and the stress-scenario selector are exercised. |

## Page-by-page findings
**Home**
- "7 ETFs" while O6 holds 6 (EEM 0%). → "6 of 7 ETFs held".
- The real-recovery figure "46%" is shown without the D39/D40 note that, with the approved quarterly rebalancing, it is about 42–45%. → note added.
- Long "What the committee needs to know" paragraph. → four short cards with a link to the page that shows the evidence.
- No guided route through the story. → page links in story order: objectives → portfolio → risk → validation → stress → decision.

**Portfolio**
- Out-of-sample underperformance in 2020–26 not visible unless the user picks that period in the table (G6). → callout comparing O6 and the policy benchmark in each out-of-sample period.

**Risk** — no factual issue. Width fix only.

**Backtest** — the one-day range crash was fixed earlier (d834fea / 02e2e89). Width fix only.

**Stress**
- D44 scenarios missing (G7).
- Scenario losses and maximum drawdowns sit in one table without saying they are different measures. → caption distinguishes peak-to-trough loss in a historical window from an instant hypothetical loss, and both from the D7 drawdown statistic.

**Sustainability** — the "Read this way" text mixes simulated and historical recovery. → split into a historical (D39) and a simulated (bootstrap) column.

**Decision** (largest change)
- A 30-row summary table first, the recommendation in a paragraph. → verdict banner, KPI cards, a limit-compliance chart (value vs limit, headroom, pass / near / breach colours), an evidence table with sources, trade-offs, monitoring ladder. The full summary table moves to an expander.
- Hard-coded figures (G5).
- "Near the limit" not distinguished from comfortable passes: P(DD > 25% in 5 y) is 4.94% vs 5% and SPY's ES share 40.0% vs a 40% cap. → amber "near limit" status when headroom is under 10% of the limit.

**Assumptions & limitations** — 106 lines of markdown on one page. → tabs per section with a compact table (short statement + D-reference + source file), the full text per section in an expander, plus a download of the source file. No text removed.

**AI disclosure** — the full markdown table is hard to read on screen. → status banner (draft / sign-off count), a compact tool table (purpose, validation), full disclosure in an expander and as a download. Data sources and the decision log stay as tabs.
